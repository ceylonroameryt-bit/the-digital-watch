Process Explorer and Autoruns for Finding Persistence

Task Manager shows you a list of names. Some you recognise, some you do not, and almost none of them tell you where they came from. When you suspect a Windows computer is infected, you need more: which program started which, whether it is signed, what it has loaded, and what will start it again after a reboot. Two small, free tools from Microsoft answer those questions better than anything built into Windows.

Tool card What they are: Process Explorer (an advanced task manager) and Autoruns (a complete list of auto-starting programs)
Made by: Mark Russinovich, Microsoft Sysinternals
Cost: free; no installation needed
Runs on: Windows 11 and Windows Server 2019 or later
Good for: spotting suspicious processes and finding how malware survives reboots
Skill level: beginner to intermediate

Why Persistence Matters

Malware that disappears when you restart your computer is of limited use to an attacker. So most of it sets up persistence: a way to start again automatically. Common methods include Run keys in the registry, the Startup folder, scheduled tasks, services and more obscure Windows hooks. Security frameworks such as MITRE ATT&CK catalogue dozens of these techniques.

Find the persistence and you usually find the malware. Remove it properly and the malware cannot come back on its own.

Malware can hide while it runs. It cannot hide the fact that something tells it to start.

Process Explorer: What Is Running, and Why

Microsoft describes Process Explorer as a tool that shows which handles and DLLs processes have opened or loaded. Its window has two parts: the top lists all active processes with their owning accounts, and the bottom shows either the handles or the DLLs of the selected process. It also has a search feature to find which process has a particular file or DLL open.

For security work, the most useful features are:

  • The process tree. Processes are shown under the process that started them. Word or Excel with PowerShell or a command prompt underneath it is a classic warning sign, the same pattern our Sigma rule looked for in Episode 05.
  • Signature verification. Turn it on from the Options menu and add the Verified Signer column. Legitimate software from major vendors is almost always signed. Unsigned programs running from unusual folders deserve a closer look.
  • VirusTotal check. Process Explorer can look up each process's file hash on VirusTotal and show the detection count in a column. Remember the lessons of Episode 07: zero detections is not proof of safety.
  • Process properties. Double-click a process to see its full path, command line, parent, network connections (TCP/IP tab) and loaded strings. Malware often runs from user folders such as AppData or Temp rather than Program Files.

Autoruns: Everything That Starts Automatically

Microsoft says Autoruns has the most comprehensive knowledge of auto-starting locations of any startup monitor. It shows programs configured to run at boot or login, from the Startup folder and Run keys to Explorer shell extensions, scheduled tasks, services, drivers, Winlogon notifications, image hijacks, WMI entries and more, organised into tabs.

The settings that make it manageable:

  • Hide Signed Microsoft Entries. Microsoft notes this option helps you zoom in on third-party items added to your system. It turns hundreds of entries into a list you can actually read.
  • Signature verification and VirusTotal, enabled from the scan options. Entries highlighted as unsigned, or with detections, go to the top of your list.
  • Missing files. Entries pointing to files that no longer exist are highlighted. Often harmless leftovers, but worth noting.
  • Jump to Entry. Takes you straight to the registry key or folder behind any item.
  • Other users. The User menu shows autostarts for other accounts on the machine.

For scripting and collecting data across many machines, the download includes Autorunsc, a command-line version. For example, autorunsc -a * -s -h -m -c lists all autostart categories, verifies signatures, shows file hashes, hides Microsoft entries and outputs CSV you can compare later.

A Simple Investigation Workflow

  1. Isolate the machine first if you suspect it is compromised, as in Playbook Monday, Episode 08.
  2. Run Process Explorer as administrator. Enable signature verification and the VirusTotal column. Look for unsigned processes, odd parent-child relationships, and programs running from user or temporary folders.
  3. Note anything suspicious: its full path, command line, hash and network connections.
  4. Run Autoruns as administrator with Microsoft entries hidden. Look for entries that match what you found, and for anything unsigned, unfamiliar or recently added.
  5. Research before you act. Look up hashes and file names. Plenty of legitimate software is unsigned or obscure.
  6. Disable rather than delete. In Autoruns, unticking an entry disables it; deleting removes it. Disabling first lets you undo a mistake.
  7. Reboot and check again. If the entry comes back, something else is recreating it.

For a fuller picture of what happened and when, combine this with Sysmon's logs from Episode 03.

Cautions

  • Download only from Microsoft's Sysinternals site or the Microsoft Store. Attackers have impersonated popular tools.
  • Be careful with VirusTotal uploads. Hash lookups share nothing, but the option to upload unknown files sends them to VirusTotal, where they may be shared. Do not upload internal or confidential programs.
  • Do not delete what you do not understand. Removing a driver or service entry can stop Windows from starting.
  • Cleaning is not the same as trusting. After a real compromise, a full rebuild from known-good media is usually the safer choice, especially if credentials may have been stolen.

Limits to Keep in Mind

  • They show the current state, not history. If malware has already removed itself, you need logs such as Sysmon to see what happened.
  • Sophisticated malware can hide from tools running on the same system, especially rootkits. Autoruns can scan an offline Windows installation to help with this.
  • Signed does not mean safe. Attackers sometimes use stolen certificates or abuse legitimate signed tools.

Final Thoughts

Run Autoruns on your own computer today, with Microsoft entries hidden. You will probably be surprised by how much starts automatically, from updaters and helpers to software you uninstalled years ago. Learning what normal looks like on a clean machine is exactly what lets you spot the one entry that does not belong on an infected one.

Know what normally starts on your computers, and anything new will stand out.

Wazuh: Open-Source Monitoring for a Small Network

Over this season we have captured packets, checked breaches, logged processes, scanned ports, written rules, decoded commands, checked files and hunted for persistence. Every one of those tools answers a question when you ask it. The final tool is different. Wazuh watches all the time, across every machine, and tells you when something needs a look.

Tool card What it is: a security platform that combines SIEM (log collection and alerting) and XDR (endpoint detection and response)
Cost: free and open source; paid cloud hosting and support available
Server runs on: Linux (Ubuntu, Red Hat, Amazon Linux and others)
Agents run on: Windows, macOS, Linux, Solaris, AIX and HP-UX
Good for: continuous monitoring of a small to medium network on a tight budget
Skill level: intermediate; comfortable with Linux helps

What Wazuh Is

Wazuh's documentation describes it as a free and open-source security platform that unifies XDR and SIEM capabilities, protecting workloads across on-premises, virtualised, containerised and cloud environments. In plain terms: it collects security information from all your computers and servers, analyses it against rules, and alerts you to things that look wrong.

It has four parts:

  • Agents, small programs installed on each computer or server you want to monitor.
  • The server, which receives data from agents and analyses it against detection rules.
  • The indexer, which stores and indexes alerts and events so they can be searched.
  • The dashboard, a web interface for viewing alerts, investigating and managing everything.

What It Watches For

Wazuh's documentation lists its main uses. The ones most useful to a small organisation:

  • Log data analysis. Collecting Windows event logs, Linux system logs and application logs, and matching them against built-in rules for failed logins, new accounts, privilege changes and much more.
  • File integrity monitoring. Wazuh records a baseline of monitored files and alerts when a user or process creates, modifies or deletes them, showing what changed, when and by whom. Ideal for system folders, web server files and configuration.
  • Vulnerability detection. Checking installed software against known vulnerabilities, so you know which machines need updating first.
  • Configuration assessment. Checking systems against security baselines, such as whether important settings are hardened.
  • Incident response. Its Active Response module can run scripts automatically when certain alerts fire, for example blocking an IP address behind an SSH brute-force attack or disabling a Linux user account.
  • Regulatory compliance. Mapping alerts and checks to frameworks such as PCI DSS and GDPR.
Individual tools answer questions. A monitoring platform asks them for you, every minute of every day.

What a Small Setup Needs

You do not need a data centre. Wazuh's quickstart covers an all-in-one installation, with every central component on one Linux machine, that it sizes for up to 100 endpoints and 90 days of searchable data:

  • 1 to 25 agents: 4 vCPU, 8 GiB RAM, 50 GB storage.
  • 26 to 50 agents: 8 vCPU, 8 GiB RAM, 100 GB storage.
  • 51 to 100 agents: 8 vCPU, 8 GiB RAM, 200 GB storage.

Installation is handled by an installation assistant script from Wazuh's official package site; follow the current quickstart for the exact command, as it changes with each version. Once it finishes, you open the dashboard in a browser, sign in with the generated admin password, and start adding agents. Larger environments should use a distributed deployment instead.

A sensible rollout for a small organisation:

  1. Start with servers and admin machines, where an intrusion would do most damage.
  2. Add Sysmon on Windows machines, from Episode 03, and configure the agent to collect its log. Wazuh then sees process creation, network connections and registry changes, not just standard Windows events.
  3. Turn on file integrity monitoring for key folders, such as web roots and system configuration.
  4. Review vulnerability results and patch the worst first.
  5. Only then consider Active Response, starting with low-risk actions.

Avoiding Alert Fatigue

The most common reason monitoring fails is not missing alerts. It is too many. People stop reading them, and the important one is lost in the noise.

  • Focus on high-severity alerts first. Wazuh rules carry levels; decide which level actually reaches someone's inbox or phone.
  • Tune out known noise with local rules, rather than ignoring the dashboard. Every alert you silence should be a decision, written down.
  • Write rules for what matters to you, such as logins outside working hours to finance systems, or new administrator accounts. The thinking is the same as the Sigma rules in Episode 05.
  • Set a routine. Ten minutes every morning reviewing the overnight alerts beats a beautiful dashboard nobody opens.
  • Plan the response before you need it. Playbook Monday, from phishing triage to isolating an infected machine, gives you the steps.

Cautions and Limits

  • Protect the Wazuh server itself. It holds sensitive data about your whole network. Keep it updated, restrict access to the dashboard, change default passwords and back it up.
  • Active Response can backfire. Wazuh's own documentation warns that poor implementation of rules and responses can increase an endpoint's vulnerability. A badly tuned rule can lock out your own staff.
  • Free software still costs time. Someone needs to install, update, tune and watch it. If nobody has that time, a managed service may be a better choice.
  • It sees only what it collects. Machines without agents, and logs you never configured, are blind spots.

Tool Spotlight, Season One in Review

Together, the ten tools in this season form a complete, free toolkit for a small security team:

  • Wireshark to see what crosses the network.
  • Have I Been Pwned to know when your details leak.
  • Sysmon to record what happens on Windows machines.
  • Nmap to map what you expose.
  • YARA and Sigma to describe threats as rules.
  • CyberChef to decode what attackers hide.
  • VirusTotal for a fast second opinion.
  • Process Explorer and Autoruns to find what is running and what comes back.
  • ZAP to test your own web applications.
  • And Wazuh, to bring it together and keep watch.

Final Thoughts: The End of Tool Spotlight, Season One

Good security is less about owning expensive products than about seeing clearly and acting quickly. Every tool in this season is free. What they need is time, curiosity and the habit of looking. Start small: one Wazuh server, a handful of agents, Sysmon on your Windows machines, and ten minutes a day with the alerts. You will know your network better within a month than most organisations ever do.

You do not need a big budget to see what is happening on your network. You need the right tools and the habit of looking.

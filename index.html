Case 03, web infrastructure and runtime

Behind the Breach: PHP2Shell — Millions of Hacking Attempts and a Race to Protect the Internet

A critical vulnerability in the web’s core runtime triggered millions of exploit attempts immediately after disclosure. But honeypot telemetry shows attackers were already testing it four days earlier.

  1. Attackers test exploit against honeypots on 17 October
  2. PHP security team discloses two CVSS 9.2 memory flaws
  3. Millions of automated scanning requests flood the web
  4. Teams race to patch runtimes before unauthenticated RCE succeeds

Case 02, retail and e-commerce

ASOS Data Breach: How One Stolen Employee Login Opened the Door to Customer Data

An attacker impersonated a trusted contact to persuade an employee to share their login. That unlocked third-party platforms holding customer names and contact details.

  1. An attacker impersonates a trusted contact
  2. An employee shares their login
  3. Third-party platforms open up
  4. Names and contact details are exposedCards and passwords were not.

Case 01, aviation and transport

Manchester Airports Group Data Breach: What Actually Happened, and Why It Matters

No flights were cancelled and no radar systems failed. But 8.8 million customers had data exposed because server-side API keys sat in client-side JavaScript for four years.

  1. Server-side API keys are placed in client-side JavaScript
  2. They stay exposed for four years
  3. Customer data becomes reachable8.8 million customers affected.
